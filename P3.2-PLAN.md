## 1. What P3.2 is, and what it is not

P3.1 built a check layer that decides three things exactly — **presence**, **absence**, and **conflict** — and refuses the fourth. Where a value is supplied and deciding whether it *satisfies* the check would require reading language, the check emits no finding and records a deferral (D-019). 116 predicate ids are declared in the registry for that fourth decision. None is implemented.

**P3.2 implements the subset of those predicates that can be decided by exact vocabulary, structural shape, numeric parsing, explicit field relationships, or existing taxonomy data — over structured values only.** Prose stays unread.

Five things P3.2 does **not** do:

| Not in scope | Why |
| --- | --- |
| Reading `narrative.*` | D-019. Prose recognition is a later phase; a predicate that reads prose is not deterministic and is not in this slice. |
| Introducing any new `FAIL` | `rubric.md` §3.1. `FAIL` needs something present to be wrong; a satisfaction predicate answers a different question. |
| Introducing any new `UNKNOWN` | A predicate only ever runs where a value **was found**. Turning a found value into absence is `FAB012_FALSE_GAP`. |
| Introducing any penalty | D6/D7 are untouched. No predicate in this slice routes to a penalty dimension. |
| Score aggregation | Not this phase (`AGENTS.md` §6). No total, no dimension subtotal, no grade. |

### 1.1 The invariant that makes P3.2 auditable

> **A recognition predicate is three-valued — `SATISFIED` / `PARTIAL` / `UNDECIDED` — and `UNDECIDED` is exactly today's deferral.**

Consequently P3.2 is **monotone over P3.1**: for every fixture, the set of `UNKNOWN` findings, the set of `FAIL` findings, and the sum of penalties are **unchanged**. The only permitted delta is that some checks which deferred now emit `PASS` or `PARTIAL`. This is a mechanical property, it is testable corpus-wide, and §7 makes it a required test.

It also means P3.2 can only move scores **upward** relative to P3.1's deflated baseline — which is the direction D-019 already named as the acceptable one, now being partially repaid with evidence rather than with a guess.

### 1.2 The two rules every predicate obeys

1. **Structured candidates only.** A predicate is evaluated against `facts.Candidate` objects whose `origin` is `merchant_structured`, reached through an exact-key path (`attributes[<key>]`, `metafields.*` on exact key equality, `variants[*].attributes`, `options[*]`, `variants[*].option_values`, `identity.*`). Candidates from `PROSE_PATHS` are never passed to a predicate. This is what preserves D-019 unchanged.
2. **No lexicon term ever reaches report text.** Lexicons are matched *against* supplied values. The only product-specific string a finding may carry is a byte-verified evidence excerpt (D-017's standing constraint, PRD §8.3 rule 4). §7 makes this an assertion, mirroring `factlex.assert_allowlist_has_no_values()`.

## 3. Per-predicate specification

Format per the task brief. **Status behaviour** always reads: what a `SATISFIED` produces, what a `PARTIAL` produces, and what `UNDECIDED` produces (always: no finding, deferral recorded — unchanged from P3.1).

Common to **every** predicate below, stated once rather than repeated:

- **Evidence consumed:** `facts.Candidate` objects with `origin == "merchant_structured"`, gathered through the check's own declared `checked_paths`. Never prose. Never the fixture envelope (PRD §5.3.1).
- **Evidence emitted:** `field_value` on the candidate whose value drove the decision, at the candidate's own `src`, byte-verified by `evidence.EvidenceBuilder`. A `PARTIAL` additionally carries the registry `question` as `remediation`.
- **Can it penalize?** **No.** None of these predicates routes to D6 or D7, and none can emit `FAIL`. The conflict path runs *before* satisfaction in `checks.attribute_check` and is untouched.
- **Confidence arm:** `recognized` (the check's `rubric.md` §4 confidence), never `structural` — a predicate decision is recognition, even when the mechanism is exact. This preserves D-020 unchanged.
- **Registry authority:** points, severity, confidence, partial credit, question and `checked_paths` continue to come from the registry. A predicate returns a verdict; it never returns a number.

### Slice A — closed vague-phrase vocabulary → `PARTIAL`

Mechanism, identical across all seven: normalize the whole candidate value (`checks._norm` — strip, collapse whitespace, lowercase, plus trailing `.`/`!`), and test **whole-value membership** in a closed phrase set transcribed from `taxonomy.md`'s own "PARTIAL if" column. Substring matching is prohibited: `"everyday"` inside a longer sentence is not the same fact as a value that *is* `"everyday"`.

| Predicate | Check | Max | Phrase set (transcribed from `taxonomy.md`) |
| --- | --- | --- | --- |
| `generic_everyday_only` | `APPAREL.INTENDED_USE_CONTEXT` | 1.65 | `everyday`, `every day`, `everyday wear`, `daily wear`, `all occasions` |
| `care_without_method` | `APPAREL.CARE_INSTRUCTIONS` | 1.65 | `easy care`, `easy to care for`, `low maintenance` |
| `easy_to_clean_only` | `HOME.CARE_AND_CLEANING` | 1.32 | `easy to clean`, `easy clean`, `wipe clean` |
| `use_as_directed_only` | `BEAUTY.USAGE_DIRECTIONS` | 2.64 | `use as directed`, `apply as directed`, `as directed` |
| `all_conditions_only` | `SPORTS.USE_ENVIRONMENT` | 1.65 | `all conditions`, `all weather`, `any conditions`, `all terrain` |
| `universal_without_list` | `ELEC.COMPATIBILITY` | 2.64 | `universal`, `universal compatibility`, `universally compatible`, `works with everything` |
| `unnamed_eco_claim` | `APPAREL.SUSTAINABILITY_CREDENTIALS` | 0.73 | `eco-friendly`, `eco friendly`, `sustainable`, `environmentally friendly`, `green` |
| `broad_family_only` | `SPORTS.SPORT_OR_ACTIVITY` | 3.30 | `fitness`, `sport`, `sports`, `training`, `exercise`, `outdoor`, `activity` |

**Exact rule.** `SATISFIED` — never returned by these; the positive arm of each owning check stays deferred. `PARTIAL` — normalized whole value ∈ phrase set. `UNDECIDED` — anything else.

**Status behaviour.** `PARTIAL`, earning `max × partial_credit` (0.5 by default, from the registry), severity `major` per `rubric.md` §5.1, confidence = the check's `recognized` arm. Evidence quotes the vague value verbatim; remediation is the registry's disambiguating question, which PRD §9.3 already requires to offer the axis of ambiguity without proposing a value.

**Can it penalize?** No.

**Fixtures/tests.** Per predicate: one fixture where the structured value is exactly the vague phrase (→ `PARTIAL`, earned = half, evidence quotes it); one where the value is a longer sentence containing the phrase (→ `UNDECIDED`, still deferred, **no** finding). One corpus test asserting no phrase-set string appears in any report text.

**Ambiguity / spec dependency.**
- `unnamed_eco_claim`: `taxonomy.md` §5.1 says an unnamed eco claim "routes to D7 as unsupported". P3.2 emits only the `PARTIAL`; the D7 route stays deferred with the rest of claim recognition. This is a deliberate partial implementation and must be stated in the commit so the D7 half is not assumed done.
- `universal_without_list`: `ELEC.COMPATIBILITY` carries `conflict_severity="blocker"`. The `PARTIAL` arm cannot reach that path — conflict is decided earlier and separately — but the check is a blocker-severity key and the fixture set must prove the two paths stay independent.
- `broad_family_only` at 3.30 is the highest-value item in this slice; its phrase list is the one most likely to be argued with. It is transcribed from `taxonomy.md`'s own example (`"A broad family ('fitness') with no discipline"`) plus the five nearest neighbours, and every addition to it is a rubric-versioned change (§6, DEC-7).
- **`all_types_without_basis` (`BEAUTY.SUITABILITY`) has this exact shape and is deliberately excluded** — beauty blocker-severity hold, §2.3(a).

### Slice B — numeric, unit and delimiter parsing

Two shared primitives, both extensions of code that already exists:

- `checks._numeric(text)` → `(magnitude, unit)` for a whole value that is one number and one unit. Already implemented, already conversion-free.
- A **closed unit vocabulary**, new in `engine/lexicon.py`: length `mm cm m in inch inches ft`, mass `g kg oz lb lbs`, volume `ml l cl floz fl oz`, time `day days month months year years yr yrs`. Normalization is the existing whitespace/full-stop rule — a formatting normalization, **not** a conversion. No entry in this table says a millilitre relates to a fluid ounce, and none may (DEC-6).

#### B1 · `material_with_proportions` / `material_without_proportions` — `APPAREL.MATERIAL_COMPOSITION`, Tier A, 3.30

- **Consumes:** structured candidate at `attributes[material_composition]` / exact-key metafield / `variants[*].attributes`.
- **Rule:** value contains `\d+(\.\d+)?\s*%` → `SATISFIED`. Value contains no `%` and no digit → `PARTIAL` (`material_without_proportions`). Value contains digits but no `%` → `UNDECIDED`.
- **Status:** `PASS` at full 3.30 / `PARTIAL` at 1.65 / deferral.
- **Penalize:** no.
- **Fixtures:** `"60% cotton, 40% polyester"` → PASS; `"cotton blend"` → PARTIAL (taxonomy's own example); `"2-ply cotton"` → deferral.
- **Ambiguity:** the rule does **not** verify that a fibre was named — it verifies that the merchant stated a proportion at a field they keyed as material composition. This is the same assumption P3.1 already makes when it awards `PASS` to any `VALUE_PRESENT` attribute at an exact key. Worth stating in the decision record because it is the load-bearing assumption of the whole slice.

#### B2 · `quantity_with_unit` / `unitless_quantity` — `BEAUTY.NET_CONTENT`, Tier A, 2.64, variant-scope non-inheritable

- **Rule:** `_numeric(value)` parses, unit ∈ volume ∪ mass → `SATISFIED`. Parses with empty unit → `PARTIAL`. Anything else → `UNDECIDED`.
- **Status:** `PASS` / `PARTIAL` / deferral — **subject to DEC-1**, because this is variant-scope and non-inheritable, so the verdict feeds coverage arithmetic rather than a single status (§5.1).
- **Penalize:** no.
- **Fixtures:** `"50 ml"` on every variant → PASS at full coverage; `"50"` → PARTIAL; `"50 ml"` on one of three variants → coverage `PARTIAL`, uncovered variants named; product-scope-only `"50 ml"` on a multi-variant product → D-018 `PARTIAL` at **zero** earned, value quoted.
- **Ambiguity:** `taxonomy.md` §5.2's `PARTIAL` column also names *"one size stated for a multi-size product"*, which is exactly D-018's case and is already handled by `checks.unresolved_scope`. The two must not both fire.

#### B3 · `dimensions_with_units` / `dimensions_without_units` — `ELEC.PHYSICAL_DIMENSIONS_WEIGHT`, Tier B, 1.65, variant-scope

- **Rule:** split the value on `x`/`×` (case-insensitive, whitespace-tolerant). ≥2 segments each parsing to a magnitude, **and** a length unit present → `SATISFIED`. ≥2 magnitudes and **no** unit token anywhere → `PARTIAL`. Otherwise `UNDECIDED`.
- **Status / penalize / DEC-1 dependency:** as B2.
- **Fixtures:** `"80 x 24 x 9 cm"` → PASS; `"80 x 24 x 9"` → PARTIAL; `"compact"` → deferral.

#### B4 · `three_dimensions_with_units` / `partial_dimensions_or_no_units` — `HOME.ASSEMBLED_DIMENSIONS`, Tier A, **4.40** (largest single D2 check in the taxonomy), variant-scope non-inheritable

- **Rule:** same segmentation as B3. **Exactly three** magnitudes and a length unit present → `SATISFIED`. Two magnitudes, or three with no unit → `PARTIAL` (matching `taxonomy.md` §5.4's "Two of three dimensions, or no units" literally). Otherwise `UNDECIDED`.
- **Status / penalize / DEC-1:** as B2.
- **Fixtures:** `"80 x 24 x 9 cm"` → PASS; `"80 x 24 cm"` → PARTIAL; `"80 x 24 x 9"` → PARTIAL; labelled form `"W 80cm D 24cm H 9cm"` → **deferral**, deliberately: parsing labelled dimension prose is recognition, and the conservative reading is the one that earns less.

#### B5 · `duration_without_coverage` — `ELEC.WARRANTY_TERM`, Tier B, 1.65

- **Rule:** the **whole** normalized value matches `\d+\s*<time unit>` and nothing else → `PARTIAL` (a duration is stated and provably nothing accompanies it). Anything longer → `UNDECIDED`. `duration_with_coverage` (the `SATISFIED` arm) **stays deferred** — recognizing a coverage scope is language.
- **Status:** `PARTIAL` at 0.825 / deferral.
- **Fixtures:** `"2 years"` → PARTIAL; `"2 years, parts and labour"` → deferral.

#### B6 · `warranty_with_duration_or_scope` — `TRUST.WARRANTY_OR_GUARANTEE`, D5, **3.00**, confidence `high`

- **Consumes:** structured candidate at `attributes[warranty_or_guarantee]`, `attributes[warranty_term]`, or an exact-key metafield. Its `narrative.description_text` path is **not** passed to the predicate.
- **Rule:** value contains `\d+\s*<time unit>` anywhere → `SATISFIED`. The predicate name is a disjunction; a stated duration satisfies the "duration" disjunct outright, so no judgment about scope is needed. No duration → `UNDECIDED` (the scope disjunct stays unread).
- **Status:** `PASS` at 3.00 / deferral. Confidence `high` is what the registry already declares.
- **Penalize:** no.
- **Fixtures:** `"2 year limited warranty"` → PASS; `"lifetime guarantee"` → deferral (no numeral; deliberately not lexiconed in this slice); nothing at any structured path, prose present → deferral, unchanged.

#### B7 · `enumerated_contents` / `contents_unenumerated` — `ELEC.IN_THE_BOX`, Tier B, 1.65

- **Rule:** split on `,` `;` newline and `•`. ≥2 non-empty segments → `SATISFIED` (the contents *are* enumerated — a structural property of the value, not a judgment about what the items are). Exactly 1 segment → `PARTIAL`.
- **Status:** `PASS` at 1.65 / `PARTIAL` at 0.825 / no deferral path (every non-empty value decides).
- **Fixtures:** `"charger, cable, manual"` → PASS; `"accessories included"` → PARTIAL (taxonomy's own example).
- **Ambiguity:** this is the one predicate here with no `UNDECIDED` arm. That is defensible — enumeration is fully structural — but it means a single-item box scores `PARTIAL` where `PASS` may be right. Flagged for review; the failure direction is the permitted one.

#### B8 · `shade_code_without_name` — `BEAUTY.COLOR_SHADE`, Tier B, 1.32, variant-scope non-inheritable

- **Rule:** whole value matches `^[A-Z0-9][A-Z0-9\-_ ]*$` with **at least one digit and no lowercase letter** → `PARTIAL` (a shade code with no name, `taxonomy.md` §5.2's own PARTIAL condition). Otherwise `UNDECIDED`. `named_shade_per_variant` stays deferred — deciding a string is a shade *name* needs a lexicon.
- **Status / DEC-1:** `PARTIAL` feeding coverage arithmetic, or deferral.
- **Fixtures:** `"N-24"` → PARTIAL; `"Warm Sand"` → deferral.
- **Note:** `color_shade` carries the default `critical` conflict severity, not `blocker`, which is why it is not in the §2.3(a) hold.

### Slice C — explicit field relationship (no lexicon at all)

These are the highest-confidence predicates in the plan: both decide by comparing **two supplied values against each other**. Nothing external is consulted.

#### C1 · `title_names_product_type` — `IDENT.TITLE_SPECIFIC`, D1, **4.00** (largest D1 check)

- **Consumes:** `identity.title`, plus `identity.product_type` and `identity.declared_category` — all structured, all already in the check's neighbourhood.
- **Rule:** let `T` = normalized title. Let `P` = the normalized `product_type` value if stated, and `C` = the normalized final `>`-delimited segment of `declared_category` if stated. If `P` or `C` occurs in `T` on **word boundaries** → `SATISFIED`. Also `SATISFIED` if the singular/plural pair differs only by a trailing `s` (`"T-Shirts"` → `"tee"` does **not** match; `"Shirts"` → `"shirt"` does). Otherwise → `UNDECIDED`.
- **Status:** `PASS` at 4.00 with **two** evidence items — a span of the title at the matched offsets, and the `field_value` of the type/category it matched — or deferral. The negative arm is never taken: a title may name a product type that is stated nowhere else, and concluding otherwise would be an unfounded `PARTIAL`.
- **Penalize:** no.
- **Fixtures:** title `"Northgate Cotton Crew Tee"` + type `"Tee"` → PASS, both locators cited; title `"The Sunday"` + type `"T-Shirts"` → deferral (`taxonomy`/`rubric`'s own negative example, and it stays silent rather than failing); title `"Storage Bin"` with product_type `"-"` (a placeholder) → deferral, because a placeholder is absent (PRD §9.4).
- **Ambiguity:** the singular/plural rule is the only soft edge. Restricting it to a trailing `s` keeps it mechanical. Anything richer is stemming, which is language recognition.

#### C2 · `title_carries_distinguishing_attribute` — `IDENT.TITLE_DISTINGUISHING`, D1, 2.00

- **Consumes:** `identity.title` plus every structured candidate anywhere in the record that carries a taxonomy attribute key (`attributes[*]`, exact-key metafields, `variants[*].attributes`, `variants[*].option_values`).
- **Rule:** if any such value — or any whitespace-delimited token of it that is ≥3 characters and not a digit-only token — occurs in the normalized title on word boundaries → `SATISFIED`. Otherwise `UNDECIDED`.
- **Status:** `PASS` at 2.00 with two evidence items (title span + the attribute at its own locator), or deferral. No negative arm, for C1's reason.
- **Penalize:** no.
- **Fixtures:** title `"Northgate Cotton Crew Tee"` + `attributes[material_composition] = "100% combed ring-spun cotton"` → PASS on the token `cotton`, both locators; title with no overlap → deferral; title overlapping only on the brand → deferral (brand is not a distinguishing *attribute*; the candidate set excludes `identity.brand` by construction).
- **Ambiguity:** the ≥3-character token rule is a stop against matching `"a"` or `"of"`. It is arbitrary in the way a threshold always is and should be recorded rather than tuned.

### Slice D — structural coverage over existing taxonomy data

#### D1 · `variant_scope_attributes_covered` — `VARIANT.ATTRIBUTE_COVERAGE`, D3, **3.00**, confidence `high`

The single best value-to-risk item in the plan: no lexicon, no language, no new vocabulary — pure arithmetic over `taxonomy_data` and the NPR.

- **Consumes:** for the assigned category, every `taxonomy_data.Attribute` with `scope == variant` and `inheritable is False`; and, per variant, the structured candidates at `variants[*].attributes` keyed to those attributes.
- **Rule:** let `K` = that attribute set and `V` = the variants. `covered = |{v ∈ V : every k ∈ K has a stated non-placeholder variant-scoped value on v}|`. `covered == |V|` → `SATISFIED`. `0 < covered < |V|` → `PARTIAL` at `max × covered/total`, with **every uncovered variant id named in the evidence** (PRD §9.7: never "some variants"). `covered == 0` → `UNKNOWN` **only if nothing is stated at any checked path for any variant**; if a product-scope value exists for one of those keys, D-018's `unresolved_scope` applies instead — `PARTIAL` at zero earned, value quoted.
- **Status:** `PASS` 3.00 / `PARTIAL` proportional / `UNKNOWN` at zero / D-018 `PARTIAL` at zero.
- **Penalize:** no. `covered == 0` with nothing found is the one path that reaches `UNKNOWN`, and `UNKNOWN` costs nothing (D-003). **This is the only predicate in the plan that can reach `UNKNOWN`, and it can do so only where P3.1 already would have** — the check's `checked_paths` are `("variants[*].attributes",)`, structured-only, so no prose gate is bypassed. Verify this against the monotonicity test in §7 before merging.
- **Fixtures:** `checks-03` (covered) and `checks-05` (partial) already exist and can be extended rather than duplicated; add an `uncategorized` product (K is empty → what then? see below) and a zero-coverage-with-product-scope-value case.
- **Ambiguity / spec dependency:** `K` is empty for `uncategorized`, and for a category whose variant-scope non-inheritable set is empty. `rubric.md` §4/D3 gives no rule. Options are `NOT_APPLICABLE` (structural, defensible — no trigger) or deferral. **Needs DEC-8.** Also depends on **DEC-1**: whether a variant whose value is only `PARTIAL` under a slice-B predicate counts toward `covered`.

#### D2 · `visual_variants_have_media` — `VARIANT.MEDIA_LINKED`, D3, 1.50, confidence `medium`

- **Consumes:** `options[*].name`, `variants[*].media_refs`, `media[*]`.
- **Rule:** a **closed visual-option vocabulary** — `color`, `colour`, `shade`, `finish`, `tone`, `pattern` — matched as whole normalized option names, exactly as `RESERVED_OPTION_NAMES` is matched today. If no option name is in the set → `UNDECIDED` (the check's structural trigger is not shown to be present; it is **not** declared `NOT_APPLICABLE`, which would remove points on an assumption). If one is: `covered = |{v : v.media_refs non-empty}|`; all → `SATISFIED`, some → `PARTIAL` proportional with uncovered variants named, none → `UNKNOWN` with `checked_paths`.
- **Status:** `PASS` 1.50 / `PARTIAL` proportional / `UNKNOWN` at zero / deferral.
- **Penalize:** no.
- **Fixtures:** a `Color` option with media on every variant → PASS; on two of three → PARTIAL naming the third; a `Size`-only product → deferral (**not** `NOT_APPLICABLE`).
- **Ambiguity:** the vocabulary is the whole risk surface and it is small and reviewable. Note that `rubric.md` §4/D3 calls this check "conditional on a visual option existing" without defining how the condition is decided — this predicate defines it, which is a spec addition and belongs in the decision record (DEC-7).

### Slice E — controlled vocabulary, positive arm

#### E1 · `named_size_standard_with_value` / `bare_size_label` — `APPAREL.SIZE_SYSTEM`, Tier A, 3.30, variant-scope non-inheritable

- **Consumes:** `variants[*].attributes[size_system]`, `variants[*].option_values` on an option named `size`, exact-key metafields.

## 4. Special attention items from the brief

### 4.1 D-018 — variant-scope handling

**Current behaviour is correct and must not change.** `checks.unresolved_scope` gives `PARTIAL` at **zero** earned with the value quoted, for a product-scope value on a non-inheritable variant attribute. Nothing in this plan touches that.

**But there is an ordering defect P3.2 must fix.** In `checks.attribute_check` step 2, `check.structural_satisfaction` is tested **before** the scope branch:

```python
if stated:
    if not check.structural_satisfaction:
        ctx.ledger.defer(...); return []
    if check.scope == "variant" and check.inheritable is False:
        return _variant_coverage(check, ctx, stated)
```

So today, every non-inheritable variant attribute that carries a recognition predicate — `size_system`, `garment_measurements`, `net_content`, `color_shade`, `assembled_dimensions`, `user_fit_specification`, apparel `color_finish` — defers *before* scope is ever considered, and D-018 never fires for them. D-018 currently applies only to `VALUE_PRESENT` attributes (home `color_finish`, sports `dimensions_and_weight`, electronics `color_finish`) and to `IDENT.IDENTIFIER_PRESENT`.

The fix is to evaluate the predicate **per candidate**, then run the scope/coverage arithmetic over the verdicts. That is a required precondition (§6, PRE-1) — and it is what makes DEC-1 blocking, because coverage over a mixed set of `SATISFIED` and `PARTIAL` verdicts has no rule in `rubric.md` today.

### 4.2 D-019 — prose deferral

**Unchanged, and structurally guaranteed.** `facts.gather` already routes `PROSE_PATHS` into `Gathered.unrecognized_prose`, a separate bucket from `candidates`. Predicates are wired to `Gathered.stated` (structured only). The step-3 gate — *"free text was found and reading it needs recognition, so absence cannot be concluded here"* — is untouched, and the "found something unread → say nothing" rule holds exactly as D-019 states it.

Two consequences worth stating explicitly:

1. A check with **both** a decidable structured value and unread prose decides on the structured value. That is already the step ordering (step 2 precedes step 3) and it is correct: something was found at a declared path and it answers the question.
2. A check with a structured value the predicate returns `UNDECIDED` for still defers, with the existing reason string. P3.2 should extend that reason to name the predicate that could not decide, so the deferral ledger becomes a measurement of the recall gap rather than an undifferentiated bucket — which is what D-019's *"that residue should be measured rather than assumed"* asks for.

### 4.3 Q-11 — category-signal disagreement

Q-11 records that `taxonomy.md` §2 rule 1 requires an `info` finding naming both disagreeing signals, that `rubric.md` §4 defines no `check_id` that could carry it, and that **"P3.1 records the disagreement on the category block's own evidence"**.

**That last statement is not currently true of the serialized output.** `classify.Classification` carries the disagreement text in `self.note`, and `Classification.as_dict()` — verified — emits only `assigned`, `method`, `confidence`, `evidence`. The note is dropped before it reaches the report shape. The two matched signals *are* quoted as evidence spans, but each carries the generic note `"Category inferred from a mapping term in the supplied data (interpreted)."`, so a reader of the report sees two mapping terms from different categories and no statement that they disagreed or that the disagreement is why the product is `uncategorized`.

**P3.2 does not need to touch classification** — no predicate in this plan reads the category block. But the decision record and the code disagree, and the honest minimal fix is to serialize `note` (and to make `_evidence_for` carry the disagreement note on the disagreement path). That is a reporting fix, not a scoring change, it creates no `check_id`, and it does not reopen Q-11's substantive question. Listed as PRE-3 (recommended, not blocking).

### 4.4 The remaining adv-03 description-placeholder gap

Reproduced against the live engine while writing this plan. `evals/fixtures/adversarial/adv-03-placeholder-values.pip.json` sets `narrative.description_text = "N/A"` and `narrative.description_html = "<p>N/A</p>"`. Two distinct defects follow:

**(a) `STRUCT.NO_PLACEHOLDER_VALUES` declares a path it does not actually search.** Its `checked_paths` include `narrative.description_text`, but `facts.gather` routes every `PROSE_PATHS` pattern into the prose bucket, and `Gathered.placeholders` reads only `candidates`. Verified: the check emits five evidence items (`identity.brand`, `identity.product_type`, two attributes, one metafield) and **not** the `"N/A"` description. On the `PASS` path the check emits absence evidence reading *"Checked and empty: no placeholder value was found at these paths"* — which, for a product whose description is literally `"N/A"`, would be a false statement about a declared path. It is a latent `FAB012`-shaped defect that today's fixture happens not to trip only because the check reaches `FAIL` on other evidence.

**(b) `IDENT.DESCRIPTION_SUBSTANCE` defers on markup wrapping a placeholder.** `facts.gather` filters placeholders out of the prose bucket (`[c for c in prose if not c.is_placeholder]`), so `description_text = "N/A"` is correctly dropped — but `description_html = "<p>N/A</p>"` is not a placeholder by `model.is_placeholder`, so it survives, `unrecognized_prose` is non-empty, and the check defers with *"free text was found at a checked path and reading it needs recognition"*. Verified in the deferral ledger. Nothing unread is actually there: the description is a placeholder, therefore absent (PRD §9.4), therefore `UNKNOWN` is the correct status and the merchant should get the question.

**Fix shape (PRE-2, blocking).**
1. Route placeholder-valued prose candidates into `Gathered.placeholders` instead of dropping them, so a check whose job is to quote placeholders sees them at every path it declares.
2. Decide `is_placeholder` for a prose HTML field on its **extracted plain text** (`htmltext`), not on the raw markup, so markup around a placeholder does not read as unread prose.

**Effect on adv-03** (implemented; measured rather than predicted): `STRUCT.NO_PLACEHOLDER_VALUES` gains a sixth evidence item quoting `"N/A"` at `narrative.description_text`; `IDENT.DESCRIPTION_SUBSTANCE` moves from *deferred* to `UNKNOWN` with `checked_paths`, zero earned, zero penalty, plus an `unknowns[]` row and a question.

A third effect this section originally missed: **twenty other `UNKNOWN` findings on the same product gain one evidence item each.** Every check that declares `narrative.description_text` and reaches `UNKNOWN` now quotes the placeholder beside its absence evidence, because `checks.unknown()` already attaches `gathered.placeholders` — PRD §9.4 requires the literal to be shown rather than silently dropped, and until now that path could never see a prose placeholder. No status, earned figure or penalty changes on any of the twenty. It is the spec-required behaviour arriving where it was previously unreachable, not a new decision.

No expectation file needed updating: `adv-03`'s expectation asserts baits and named invariants, not the per-check status map (`status_coverage: "partial"`). The corpus-wide status pin now lives in `evals/expected/monotonicity_baseline.json` instead (§7.1).

**Why it is a precondition rather than a follow-up:** P3.2 makes the structured/prose split load-bearing for scoring. Shipping recognition on top of a gatherer that mis-buckets placeholder prose would bake the defect into every predicate that declares a prose path alongside a structured one.
